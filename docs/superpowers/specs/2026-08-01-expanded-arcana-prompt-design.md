# 확장 메이저 아르카나 프롬프트 설계

## 목표

`major-arcana-ko-v4-expanded.md`의 22장 해석 내용을 새 활성 카드 프롬프트로 적용한다.
카드별 다중 문단을 지원하도록 파서를 확장하면서도 실제 선택된 카드만 OpenAI 요청에
포함하고, 파일명 기반 `prompt_version` 기록을 유지한다.

리딩은 오락성과 타로다운 재미를 위해 미래 흐름과 상대방 감정·의도에 관한 상징적
예측을 허용한다. 다만 공포를 키우거나 중대한 결정을 유도하는 확정적 예측은 금지한다.

## 리소스 형식

새 파일은 다음 heading으로 카드 섹션을 구분한다.

```markdown
## major-00-fool / 바보

카드 해석 내용

## major-01-magician / 마법사

다음 카드 해석 내용
```

첫 카드 heading 이전 내용은 preamble이다. 마지막 카드 섹션은 파일 끝까지 포함한다.
별도 postamble이 필요한 경우 마지막 카드 다음에 `## 카드 공통 안내` heading을 사용한다.
파서는 이 heading부터 파일 끝까지를 postamble로 취급한다.

카드 섹션 내부의 `핵심 주제`, `자연스러운 발현`, `성장 과제`, `그림자 발현`,
`그림자가 지키려는 것`, `가능한 발현`, `관련 감정`, `성찰의 방향`은 파서가 해석하지
않는다. 카드 heading 경계 안의 Markdown을 하나의 불투명한 해석 재료로 보존한다.

## 파서 계약

`TarotPromptCatalog`는 다음 규칙을 적용한다.

1. `## major-{두 자리 번호}-{slug} / {표시 이름}` 형식만 카드 시작으로 인식한다.
2. heading에서 추출한 ID는 `MajorArcana`의 canonical ID여야 한다.
3. 22개 canonical ID가 각각 정확히 한 번 존재해야 한다.
4. 중복, 누락, 미지원 ID, 비어 있는 카드 섹션은 초기화 실패로 처리한다.
5. 선택 시 요청받은 card ID 순서대로 전체 카드 섹션을 합성한다.
6. 선택되지 않은 카드 섹션은 합성하지 않는다.
7. preamble과 postamble은 선택 카드 앞뒤에 한 번씩 보존한다.

기존 한 줄 `- major-* / ...` 형식과의 동시 지원은 하지 않는다. 활성 v4와 테스트 fixture를
새 형식으로 함께 전환해 파서 분기를 단순하게 유지한다. 이전 v2·v3 파일은 운영 추적을
위해 보존하지만 더 이상 새 파서의 입력으로 사용하지 않는다.

## 프롬프트 구성

공통 프롬프트는 새 버전으로 추가하고 다음 원칙을 적용한다.

- 카드의 8개 항목을 모두 나열하지 않고 질문과 position에 가장 관련 있는 2~3개만 고른다.
- `가능한 발현`, `관련 감정`, `그림자가 지키려는 것`은 사실이 아니라 해석 후보로 다룬다.
- 심리학적 라벨을 그대로 출력하지 않고 짧고 쉬운 일상어로 풀어 쓴다.
- 질문에 구체적인 근거가 있으면 그 근거와 카드 의미를 연결한다.
- 근거가 부족한 세부사항은 사실처럼 창작하지 않는다.

기존 말투, 가독성, guidance, summary, JSON 출력, prompt injection 방어 원칙은 유지한다.

## 예측 정책

허용하는 표현:

- 카드가 보여주는 가까운 미래의 분위기와 전개 가능성
- 현재 흐름이 이어질 경우 나타날 수 있는 관계·선택의 방향
- 상대방 감정이나 의도에 관한 상징적 가능성
- 긍정적 또는 부정적 결과에 대한 조건부 전망

예측임을 드러내기 위해 `가능성이 커 보여요`, `이 흐름이 이어진다면`,
`카드상으로는 이렇게 읽혀요`와 같이 여지를 남긴다. 모든 문장을 방어적으로 만들 필요는
없지만, 확인되지 않은 내용을 이미 드러난 사실처럼 쓰지 않는다.

금지하는 표현:

- `반드시`, `확실히`, `무조건`처럼 결과를 보장하는 단정
- 배신, 외도, 임신, 질병, 사망, 범죄, 파산, 재난을 카드만으로 확정하는 주장
- 공포·죄책감·의존을 키워 결제나 반복 리딩을 유도하는 표현
- 타로만을 근거로 이별, 퇴사, 투자, 치료 중단 등 되돌리기 어려운 행동을 지시하는 것
- 의료·법률·재정·위기 상황에서 전문적 판단을 대체하는 조언

## 버전과 활성 설정

- 카드 리소스는 `major-arcana-ko-v4.md`로 추가한다.
- 공통 프롬프트는 의미 변경을 반영해 새 버전으로 추가한다.
- `src/main/resources/application.yaml`에서 두 새 리소스를 활성화한다.
- spread 프롬프트는 position 및 출력 계약이 바뀌지 않으므로 현재 버전을 유지한다.
- `TarotPromptCatalog.version()`은 선택 리소스 파일명에서 기존 방식대로 버전을 조합한다.

## 테스트

한국어 카피를 assertion하지 않고 합성 Resource 기반 구조 계약을 검증한다.

- 22개 canonical ID의 다중 문단 섹션을 정상 파싱한다.
- 누락, 중복, 미지원 ID, 빈 섹션을 거부한다.
- 선택 카드만 요청 순서대로 합성한다.
- preamble과 `## 카드 공통 안내` postamble을 보존한다.
- 파일명에서 prompt version을 생성한다.
- 운영 YAML의 활성 리소스가 실제로 존재하고 읽을 수 있다.
- OpenAI 생성기의 schema, position 순서, 선택 카드 전달 계약이 유지된다.

관련 테스트 통과 후 마일스톤 종료 직전에 전체 Gradle 테스트를 한 번 실행한다.

## 비범위

- 카드별 파일 22개로 분리
- 기존 generation record의 prompt version 마이그레이션
- 실제 OpenAI 호출을 사용하는 자동 품질 평가
- spread position 또는 JSON 응답 스키마 변경
