# M4 — 월별로 다시 찾아 읽는 한 해 리포트

## 목표와 사용자 경험

종합 사주는 유지하고 사주 시작 화면에서 한 해 리포트를 선택한다. 기존 안내형 입력 여정에서 올해·내년, 관심사(필수), 질문(선택), 출생정보를 받는다. 질문이 없으면 대신 만들지 않는다.

결과는 연간 개요 → 12개월 카드 → 선택한 월의 상세 → 최종 요약 순서다. 올해는 이번 달, 내년은 1월을 기본 선택하고 개인정보 없는 month URL로 선택을 보존한다. 월 상세는 월 요약·절입 전후 해석·계산된 적용 기간을 보여 준다. 두 달에 걸친 같은 구간의 해석은 공유하며 연결 안내를 제공한다. 계산 상세는 접고 제한사항·안전 안내·내 사주 탐색은 유지한다. 문체는 자연스러운 한국어를 우선한다.

후속 사용자 승인: 일간이 확정되지 않은 경우에는 간략형으로 제공한다. 연간 개요·12개월 한 줄 요약·계산된 적용 구간은 유지하고 구간별 장문은 생성하지 않는다. 상세형/간략형은 요청자가 임의로 고르는 옵션이 아니라 계산에서 확정된 근거로 결정한다. 출력의 detailLevel로 구분한다.

점수·행운 날짜·사건 확률·공유 카드·알림·전체 대운 타임라인은 제외한다.

## 생성과 호환 계약

공개 연결은 M4-B에서 한다. reportType 생략은 birth_annual_question이며 기존 schema v6을 유지한다. annual_monthly는 신규 schema v7을 사용한다. 유형을 요청 지문·생성기·프롬프트 버전·가격 선택에 반영한다. 기존 기록은 변경하거나 재계산하지 않는다.

M3 월운에서 연속한 동일 구간을 합쳐 안정적인 ID를 부여하고 월별로 참조한다. AI는 원국·연운·월운·ID만 사용하며 날짜는 계산값으로 표시한다. 출생 원문·좌표·후보 출생시각은 저장·전송하지 않는다. 확정 일간이 없으면 개인 십성을 사용하지 않으며 계산되지 않은 관계를 AI가 보충하지 않는다.

연간 개요, 12개 월 요약, 구간별 해석, 선택적 질문 답변, 최종 요약과 기존 안전 필드를 생성한다. 정상 보고서는 모든 월과 구간이 완성되어야 한다. 같은 근거에 억지 차이를 만들지 않는다. 기존 safety/common/interpretation/report 역할은 유지하고 새 report를 추가한다.

간략형은 구간별 해석이 빈 배열이며 계산 캘린더는 그대로 유지한다. 모델용 schema는 월/구간을 고정 key 객체로 받아 각 문단의 근거 enum을 해당 범위로 제한한다. 서버가 고정 key를 순서 있는 결과 DTO 배열로 변환한다. 잘못된 참조·중복 JSON·후행 JSON·scalar coercion을 허용하지 않는다.

## M4-A — 비공개 검증 후 가격 확인

연간 DTO·입력 매핑·프롬프트·생성기·검증기·AI-preview만 구현한다. 공개 controller·DB·가격·사용자 UI는 변경하지 않는다. 기존 키와 설정 모델을 사용한다.

합성 8사례(4개 관심사, 무질문·단일·복합 질문, 근사 경계, 시간 미상/일간 확정, 일간 미확정, 안전 전환)를 실행하고 무질문·복합·불확실·안전 4사례를 재검증한다. 첫 평가 묶음은 최대 12회다. 모델·프롬프트 버전·토큰·시간·공식 단가에 따른 비용을 기록한다.

정상 결과의 12개월/전체 구간 완성, 근거·날짜 일치, 동일 구간 공유, 질문 충실도, 안전 기준을 확인한다. 가독성·질문 답변·구간 구분·반복 정도를 각 5점 중 4점 이상으로 평가한다. 120초 이내 완료, 목표 90초 이내이며 미달 시 전역 timeout을 늘리지 않는다. 품질이나 시간 기준이 미달이면 공개 준비로 넘어가지 않는다.

실제 측정 결과를 보고하고 사용자에게 연간 리포트의 크레딧을 확인받은 후 M4-B로 진행한다. 종합 사주의 4크레딧을 자동 적용하지 않는다.

## M4-B — 승인된 가격으로 저장·화면 연결

사용자가 M4-A 품질·실측 결과를 확인한 뒤 상세형·간략형 모두 4크레딧으로 승인했다. 추가 실제 AI 호출 없이 승인된 합성 Preview 결과와 mock을 재사용해 M4-B를 검증한다.

신규 migration으로 v7만 추가하고 v5/v6·기존 migration을 보존한다. 한 번 완성해 저장한 결과를 월 전환·새로고침·기록 복원에서 재사용한다. 완성 검증 후에만 완료 처리·차감하고 실패는 차감하지 않는다. 명시적 실패는 새 requestId, 모호한 전송 실패는 기존 requestId를 유지한다. 월별 재생성은 지원하지 않는다. 새 연도/새 생성에 필요한 출생정보는 다시 입력받는다.

단계 중 관련 테스트만 실행하고 M4 최종 종료 전 전체 검증 1회, Review Desk 리뷰/수정/재리뷰를 거친다. 요청 스레드 ID를 포함한다. approved 후 오더/보고 로그에 M4 보고 1개를 작성한다. 공통 정책·계약·사용자 변경 공지를 반영한다. M3 승인 커밋 위 독립 M4 브랜치를 사용하며 push·PR·merge는 사용자 담당이다.
