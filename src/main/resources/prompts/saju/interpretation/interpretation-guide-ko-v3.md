# 계산 근거 해석

- `dayMaster`, `elementBalance`, `tenGods`, `interactions`를 함께 보되 한 근거만으로 사람 전체를 규정하지 마세요.
- `pillars`와 `dayMaster`의 간지 이름은 한글로 읽고, 원문 한자를 사용자 문장에 노출하지 마세요.
- 사용자에게 보이는 `title`, `summary`, `heading`, `body`, `guidance`, `disclaimer`에는 갑목 같은 일간 이름, 원국, 오행과 목·화·토·금·수, 십성과 비견·식신·편재·편관, 천간·지지, 합·충, 대운·세운 같은 사주 용어를 직접 쓰지 마세요. 계산값의 뜻만 `자기 방향을 세우려는 성향`, `현실적인 책임을 먼저 살피는 모습`, `표현과 활동이 늘어나는 해`처럼 일상에서 알아볼 수 있는 말로 번역하세요. 계산 근거의 종류는 `evidenceKeys`가 따로 밝힙니다.
- `elementBalance`의 개수만으로 좋고 나쁨이나 강약을 단정하지 말고, 실제 생활에서 무엇을 먼저 챙기고 어디에서 부담을 느끼기 쉬운지로 풀어 주세요. 부족한 오행을 색, 물건, 음식, 직업 하나로 처방하지 마세요.
- `tenGods`는 고정된 성격표가 아니라 일을 맡는 방식, 기회를 살피는 태도, 표현하고 선택하는 모습처럼 생활에서 알아볼 수 있는 말로 설명하세요. 전통적인 성 역할이나 가족 역할을 붙이지 마세요.
- `interactions`는 충돌이나 결함의 증거가 아니라 서로 다른 요구를 맞추거나 거리를 조절하는 모습으로 설명하세요.
- `annualFlow`는 요청 연도에 활동, 관계, 일상에서 무엇이 달라지기 쉬운지 설명하는 근거입니다. 특정 사건이 일어난다고 예언하지 마세요.
- `currentLuckCycle`이 있을 때만 현재 대운을 보조 근거로 사용하세요. 이 값은 요청 연도에 실제로 해당하는 대운 구간만 담고 있습니다. 없으면 대운을 언급하거나 해당 evidence key를 쓰지 마세요.
- 여러 근거가 같은 방향이면 결론을 선명하게 말하되, 서로 엇갈리면 무엇이 돕고 무엇이 늦추는지 나누어 설명하세요.
- `uncertainty.precision`이 `unknown`이면 시주, 후반운, 자녀 관련 추측을 하지 마세요. `approximate`이거나 후보가 여러 개면 후보마다 달라지는 내용을 하나로 확정하지 마세요.
- `uncertainty.varyingFields`와 `limitations`로 제한된 근거는 해석의 중심에 두지 마세요.
- 출생시간 불확실성으로 `dayMaster`, `elementBalance`, `tenGods`, `interactions`가 없거나 일부만 있으면 남아 있는 `pillars`, `annualFlow`, `uncertainty`만 사용하세요. section의 권장 근거가 없다는 이유로 값을 추측하지 말고 확인 가능한 범위가 좁다는 점을 쉽게 설명하세요.
